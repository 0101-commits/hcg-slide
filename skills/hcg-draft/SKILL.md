# HCG 제안서 초안 (hcg-draft)

요청서(RFP)·회의 메모·통화 메모를 읽고, 제안서의 뼈대를 설계해 돌려준다. 사람들이 「/hcg-초안」이라 부르던 작업임. 슬라이드를 직접 조립하는 일이 아니라 「무엇을 어떤 순서로 몇 장, 어떤 주장으로 쓸지」를 정하는 일이다.
문체는 우리말 「~함」. 영어식·개발자 말투를 쓰지 않는다(파일·코드 이름만 영문).

## 이 스킬이 돌려주는 것

1. 요청 대응표: 요청 → 장표, 판정은 충분 / 부분 / 누락 / 본문 밖
2. 목차 5유형 중 추천과 까닭
3. 섹션별 장수
4. 장별 제목 + 주장 문장(결론형 한 문장) + Library 유형 후보(목적 코드 P01~P26, 구조 코드)
5. 새로 써야 할 장표 목록(메시지 초안 한 줄씩)
6. 맞서는 규칙은 조건을 물어 확정

가격 장표는 만들지 않는다. 「본문 밖」 표시만 한다. 지어낸 숫자는 본문에 「(가정)」을 붙이고 「확인해 주실 점」에 다시 올린다. 근거 자료가 없으면 「근거 부족」으로 표시하고 지어내지 않는다.

## Dummy 제안서(고객사명 · 회의 내용 · 스콥 → Dummy 장)

「Dummy 제안서」「더미 만들어 줘」 요청이면 `references/dummy.md` 대로 한다. 장마다 `references/types.md` 의 유형 코드를 골라 Dummy 장(어깨끈 · 핵심 문장 · ///)을 만들고 유형 표시를 붙인다. Claude for PowerPoint 에서는 Office 명령 실행 도구로 직접 만들고, 다른 곳에서는 HCG_PLAN 블록을 준다. 실제 장표는 「HCG 장표」 작업창의 「Library로 채우기」가 넣는다.

## 어디서 돌리느냐

### 1. Claude 앱(데스크톱·웹)
사용자가 요청서(PDF·DOCX·PPTX·텍스트)나 메모를 올림. 파일을 읽어 아래 절차대로 대화로 결과를 돌려준다. 이 스킬은 스크립트가 필요 없다. 표가 길면 대화에 표로 쓰고, 파일이 필요하다고 하면 마크다운 파일로 만들어 돌려준다. 참고 제안서가 올라오면 `hcg-check` 의 `scripts/extract_text.py` 로 장 제목을 뽑아 재사용 후보를 고른다.

### 2. Claude for PowerPoint
파일 시스템·파이썬이 없음. 열려 있는 덱을 `read_slide_text`·`list_slide_shapes` 로 읽어 참고하고, 결과는 대화에 표로 적는다. 사용자가 「이 틀로 장을 만들어 줘」라 하면 `duplicate_slide` 로 비슷한 장을 복제한 뒤 `edit_slide_text` 로 글을 바꾸고 `verify_slide_visual` 로 넘침을 확인한다. 「HCG 장표」 작업창이 목적 코드·칸 번호·글자 수 한도를 붙여 넘기면 그 한도를 지킨다. 그 뒤의 구조 변경은 `hcg-restructure`, 점검은 `hcg-check` 로 넘긴다.

### 3. Claude Code(CLI)
PC 에서 폴더째 작업 가능. 과거 제안서 폴더가 있으면 파일 이름·장 제목을 훑어 참고 후보를 고른다. 원본 제안서 폴더는 읽기만 하고 쓰지 않는다. 결과 표를 파일로 저장해 달라고 하면 새 파일로 저장한다.

## 절차

1. 입력 읽기 → `references/questions.md` 를 읽고, 필수 10개 중 글에서 찾은 것은 채워 확인만 받고 못 찾은 것만 묻는다. 발주처가 공공기관이거나 입찰 규정이 있으면 규정 질문도 묻는다. 문서 유형이 제안서가 아니면 경량 골격(같은 파일 끝)을 쓴다.
2. 요청 표 → 요청 원문에서 요청 항목을 뽑아 번호를 붙인다. RFP 항목 번호가 있으면 그 번호와 맞춘다. 별도 제출물(가격·서식·서약서)은 「본문 밖」으로 따로 모은다. 분량·기간 제약도 뽑는다.
3. 짜임 고르기 → `references/toc_and_messages.md` 로 목차 유형·섹션 장수를 정하고, `references/request_bundles.md` 로 요청 유형마다 장표 묶음을 붙인다. 판정(충분/부분/누락)은 같은 파일의 기준대로.
4. 규칙 적용 → `references/rules.md` 에서 해당 규칙(「언제 → 무엇을」)을 골라 적용한다. 맞서는 규칙(회사 소개 5장 vs 생략, 일정 두 안, [참고] 강등, 시스템 축)은 임의로 정하지 말고 가르는 조건을 사용자에게 묻는다. 분량이 RFP 범위와 충돌하면 경고와 줄일 후보만 낸다.
5. 장별 줄거리 → 장마다 제목 + 주장 문장 + Library 유형 후보(`references/codes.md`)를 적는다. 문체는 `references/hcg_style.md`.
6. 결과 → `references/output_format.md` 의 형식대로 돌려준다. 끝에 「확인해 주실 점」을 모은다.
7. 이어서 → 초안 슬라이드가 만들어지면 「점검」으로 `hcg-check` 를 권한다(이전 고객명·자리표시자·회사 수치).

## references 읽는 때

| 파일 | 언제 읽나 |
|---|---|
| `questions.md` | 처음 입력 받을 때, 문서 유형·공공 규정 확인 |
| `toc_and_messages.md` | 목차 유형·장수·메시지 문형·Why HCG·맞춤 방식을 정할 때 |
| `request_bundles.md` | 요청 항목을 장표 묶음에 붙이고 판정할 때, 회의 피드백 처리 |
| `rules.md` | 생성 규칙(약 60개)과 맞서는 규칙을 적용할 때 |
| `codes.md` | 목적 코드·구조 코드로 Library 유형 후보를 적을 때 |
| `hcg_style.md` | 주장 문장·제목을 쓸 때 |
| `output_format.md` | 결과를 돌려줄 때 |

## 지킬 것

- 이 규칙들은 「HCG 가 실제로 한 방식」이지 「수주한 방식」이 아니다(결과 표시가 있는 과거 건이 10건뿐). 「이렇게 하면 수주한다」고 말하지 않는다.
- 첫 초안은 최종과 40~70%만 겹치고 장표의 약 40%가 빠지는 것이 보통이다. 장표 묶음 단위로 켜고 끌 수 있게 내고, 사람이 고칠 것을 전제로 한다.
- 고객명·수치·날짜를 지어내지 않는다. 회사 소개 수치는 `hcg-check/references/company_figures.json` 의 값(관리자 확인 필요 표시)과 기준월을 함께 쓴다.
- 사용자 입력이 부족해 추정한 것은 모두 표시한다(「요청 추정」「(가정)」「근거 부족」).
