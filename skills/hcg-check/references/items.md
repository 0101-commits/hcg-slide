# 점검 28항목 (자동 16 · 반자동 12 · 공공·입찰형 5가 이 안에 포함)

근거 = 그 고침·규정이 실제로 나온 프로젝트 수(「—」는 사용자 지적, 11-02). 처리 = 자동(스크립트가 판정) / 반자동(스크립트는 후보만, Claude 가 문장·문맥 판단). 번호는 `check.py` 의 항목 번호와 같다.
규칙·구조 점검은 도구가 바로 고치거나 고칠 안을 내고, 문장·입력 대조는 고칠 안을 내면 사람이 정한다. 공공·입찰형 규정 점검(24~28)은 발주처 규정(`rules.json`)이 있을 때만 켜진다.

## 스크립트가 못 하는 것 (Claude 가 해야 할 것)

- 반자동 12항목은 후보만 나온다: 후보를 읽고 정말 문제인지 판단하고, 14·15·16 은 고칠 문장 후보 2개를 쓴다(문체는 `hcg-draft/references/hcg_style.md`).
- 6번(출처): 수치가 고객 공개자료인지 HCG 추정인지는 문맥을 보고 판단.
- 18번(요청 대응): 판정(충분/부분/누락)은 스크립트의 키워드 일치 후보이므로 장표 내용을 읽고 확정.
- 21번: 고객 업종과 인력 실적의 관련성은 Claude 가 판단.
- 24번 「유추 가능」: 확정하지 말고 후보로 보여 주고 사람이 정하게 한다.
- 도형이 그림으로 된 로고·차트 안의 글·SmartArt 안의 글은 텍스트 추출에 안 잡힐 수 있다. 무기명 점검에서는 이 한계를 반드시 알린다.
