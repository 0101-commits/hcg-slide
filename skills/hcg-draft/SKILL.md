# HCG 제안서 Draft 만들기

사람이 할 일은 ① 회의록(고객 내용) 붙여넣기(+ 자료 폴더 경로) ② 질문 카드 답 ③ 계획 표 확인 한 번 ④ 받은 파일 손보기 뿐이다. 나머지는 아래 순서대로 **멈추지 않고** 한다.
- 회의록만 받아도 이 순서를 처음부터 끝까지 한다. 사용자가 「물어봐」라고 하지 않아도 **1단계가 끝나면 바로 질문 카드**를 띄운다.
- 계획 확인(3단계) 전에는 장표 파일을 만들지 않고, 골격 문서 · 요약 파일 같은 다른 결과물도 만들지 않는다.
- 말투: 우리말 해요체, 짧게. 영어 · 개발 용어를 쓰지 않는다. 진행 중에는 단계마다 한 줄씩만 알린다(「계획을 짜는 중이에요(약 5분 — 고객 자료까지 읽어요)」).

## 고정 값
- `<스킬>`: 이 스킬을 불렀을 때 맨 위에 나오는 「Base directory for this skill」 경로.
- 단계 명령 `hcgd <단계> ...` 은 실제로 이렇게 부른다(이 모양 그대로여야 승인 창 없이 돈다):
  - PowerShell 도구: `cmd /c <스킬>\scripts\hcgd.cmd <단계> ...` — 스킬 경로는 따옴표 없이. 작업 폴더 같은 인자는 큰따옴표로.
  - PowerShell 도구가 없거나 스킬 경로에 띄어쓰기가 있으면 Bash 도구: `powershell -NoProfile -ExecutionPolicy Bypass -File "<스킬>\scripts\hcgd.ps1" <단계> ...`
  - 한 번에 명령 하나만(`;` · `&&` 로 잇지 않음). 아래에서는 줄여서 `hcgd <단계> ...` 로 쓴다. 데이터 폴더(열쇠 · 창고 목록, `%LOCALAPPDATA%\HCG\draft`)는 명령이 알아서 쓴다 — 넘기지 않는다.
- 명령 결과는 JSON 한 줄. `error` 가 있으면 그 문장을 사용자에게 그대로 전하고 멈춘다. `error_code` 면 아래 「준비 오류」 표의 문장을 전하고 멈춘다.
- `build` · `apply` · `fix` · `finish` 는 몇 분 걸릴 수 있다. 도구 timeout 을 600000(10분)으로 주고, 백그라운드로 돌리지 않는다. 기다리는 동안 다른 명령(sleep · 감시)을 끼우지 않는다.

## 0. 준비
- **PC 확인:** PowerShell 도구도 없고 Bash 에서 `powershell` 이 없으면(웹 채팅 · PowerPoint 안 Claude · 리눅스) 「제안서 Draft 는 Windows PC 의 Claude 앱 「Code」 탭(또는 Claude Code)에서 만들 수 있어요. Dummy 장만 필요하면 「Dummy 제안서 만들어 줘」라고 해 주세요.」라고 하고 멈춘다.
- 「준비하는 중이에요(처음 한 번은 1분쯤 — 준비물을 받아요)」 한 줄 알리고 `hcgd setup`
- `ready: true` → 다음으로.
- `ready: false` 이고 열쇠 이야기면: 「처음 한 번만 열쇠가 필요해요. https://hcg-slides.pages.dev/key 를 열어 회사 메일로 로그인한 뒤 「열쇠 받기」를 누르고, 받았다고 말해 주세요.」 → 답이 오면 setup 을 다시. **열쇠 글자를 대화에 붙여 달라고 하지 않는다.**
- `powerpoint: false` → 「이 PC에 PowerPoint 가 없어 넘침 검사와 그림 확인은 건너뛰어요」라고 알리고 진행.

### 준비 오류(`error_code`)
| 값 | 사용자에게 |
|---|---|
| `download` | 준비물(약 20MB)을 GitHub 에서 받지 못했어요. 인터넷 연결을 확인하고 다시 해 볼게요 — 계속 안 되면 회사 방화벽에서 github.com 이 막혔는지 관리자에게 물어봐 주세요. |
| `hash` | 받은 준비물이 원본과 달라 쓰지 않았어요. 관리자에게 알려 주세요. |
| `unpack` | 준비물을 푸는 데 실패했어요(디스크 공간 · 백신 확인). 관리자에게 화면을 보내 주세요. |
| `not_windows` · `no_runtime_json` | 이 PC 에서는 돌릴 수 없어요 — Windows PC 의 Claude 앱 「Code」 탭에서 해 주세요. |
`download` 는 한 번만 다시 시도한다.

## 1. 회의록 읽기 → 작업 폴더
1. 글에서 고객 약칭을 찾아 `hcgd workdir "<고객 약칭>"` → `dir` 이 **작업 폴더**(`문서\HCG Draft\<약칭>_<YYMMDD>`, 빈 `자료` 폴더 포함, 같은 이름이 있으면 `_2`). 결과 파일도 여기 생긴다.
2. 사용자가 붙인 글(명령 줄 · 「자료 폴더:」 줄 빼고)을 그대로 `작업 폴더\input.txt` 로 쓴다(Write).
3. 글에서 찾은 것으로 `작업 폴더\client.json` 을 쓴다:
   `{"short": 고객 약칭, "names": [고객 이름 · 영문 · 옛 이름 · 계열 이름], "dart": 상장사면 DART 회사 이름(모르면 약칭), "excl": names 를 | 로 이은 것, "ind": 업종(아래 목록 중 하나), "title": 과제 이름(예 「평가제도 고도화」), "project": 표지 제목(예 「평가제도 고도화 프로젝트」), "date": 이번 달 「YYYY. MM」, "body": 글에 분량이 있으면 그 장수 아니면 40}`
   (body = Ⅰ~Ⅲ장 본문 장수. 표지 · 목차 · 간지 · HCG 소개는 빼고 센다)
   업종 목록: 금융 · 자동차·기계·중공업 · 식품·소비재 · 지주·그룹 · IT·플랫폼·게임 · 화학·소재·에너지 · 공공·연구 · 건설·부동산 · 바이오·제약 · 유통·서비스·레저 · 전자·반도체 · 물류·운송 · 교육·미디어 · 기타
4. 붙인 글에 「자료 폴더: <경로>」가 있으면 **먼저** `hcgd docs "<작업 폴더>" "<경로>"` → 읽은 파일 · 못 읽은 파일(`read` · `failed`). 스캔 PDF 는 Windows OCR, 옛 .doc 는 Word 로 읽는다(몇십 초). 그다음 `docs.md` 를 앞에서부터 필요한 만큼만 읽어(현행 제도 · 인원 · 일정 · 요청 위주) 「찾은 것」에 더한다. 원본 폴더에는 아무것도 쓰지 않는다.
5. `hcgd start "<작업 폴더>"` → 기준 제안서 후보 3건(`proposals`, 과제 분류 · 업종 · 고객 자료로 고름) · 상장 여부(`listed`). 카드에서 자료 폴더를 받았으면 docs 뒤에 start 를 한 번 더 불러 후보를 새로 받는다.
6. 사용자에게 「회의록 · 자료에서 찾은 것 / 못 찾은 것」을 짧은 목록으로 보여 주고 **곧바로** 2단계 질문 카드를 띄운다. 기준은 [questions.md](references/questions.md) 의 필수 10개.

## 2. 질문 카드 (AskUserQuestion, 한 장에 4문항까지)
선택지 문구 · 미리 고른 값은 [questions.md](references/questions.md) 대로. 질문 · 선택지 · 설명은 모두 한국어.
- **카드 1(늘 묻는다):** 자료 폴더(붙인 글에 경로가 없을 때만 — 없으면 이 자리에 회사 소개) · 분량(본문 Ⅰ~Ⅲ장 장수) · 기준 제안서(후보 3건 + 기준 없이) · 고객 숫자(`listed: true` 일 때만 「DART 원문에서 찾아 넣기」)
  회의록에 이미 값이 있으면 그 값을 첫 선택지(Recommended)로 두되 카드는 띄운다. 자료 폴더 답이 오면 1-4 처럼 `hcgd docs` 로 읽는다.
- **카드 2:** 회사 소개(Ⅳ장, 표준 5장 — 카드 1 에서 안 물었으면) · 제출일 · 고객 로고 파일 + 회의록 · 자료에서 못 찾은 필수 항목(문서 유형 · 발주처 유형 · 기간 · 투입 인력 · 가격 처리 중 없는 것). 4문항이 안 차면, 회의록에서 판단이 갈리는 **내용 질문**(예: 반영 비율을 옵션으로 보일지 · 단계적 도입으로 쓸지 · 이전 제안 이력을 쓸지)을 1~2개 더한다. 공공기관이면 입찰 규정 카드를 한 장 더.
- 답을 client.json 에 더한다: `"body"`, `"base_doc"`(고른 후보의 doc, 기준 없으면 ""), `"numbers"`(`dart`|`paste`|`blank`), `"intro"`(`그대로`|`4장`|`빼기`), `"date"`, `"logo"`(파일 경로 또는 ""), `"people"`, `"price"`. 내용 질문의 답 · 투입 인력 · 「내가 붙여 넣기」로 받은 숫자는 input.txt 끝에 「# 확정 사항」으로 덧붙인다.

## 3. 계획 → 확인 「이대로 만들까요?」(한 번 멈춤)
1. `hcgd plan "<작업 폴더>"` → `prompt` · `plan` 경로, 찾은 공시 숫자(`disc`).
2. **계획 에이전트**(아래 「에이전트 부르기」)를 부른다: 일 = 「요청문 <prompt> 를 읽고 계획을 <plan> 에 써라」.
   그다음 `hcgd plan-check "<작업 폴더>"` → `prompt` 가 있으면(핵심 메시지가 70자 미만 · 115자 넘는 장 4장 이상) **계획 에이전트**를 한 번 더: 일 = 「요청문 <prompt> 를 읽고 <plan> 을 고쳐 써라」. 한 번만 한다.
3. `hcgd plan-table "<작업 폴더>"` 의 표를 그대로 보여 주고 AskUserQuestion 하나: 「이 계획으로 만들까요?」 — 이대로 만들기 / 몇 장 바꾸기(번호와 바꿀 내용 적기) / 분량 다시 정하기.
4. 바꾸기면 plan.json 의 그 줄만 고친다(다른 장이 필요하면 요청문의 후보 목록에서 id 를 고름). plan-table 로 고친 표를 다시 보여 주고 다시 묻는다. 분량 다시면 2절 분량만 다시 묻고 3-1 부터.
- Ⅲ장(추진 일정 · 수행 조직 · 투입 인력) 핵심 메시지는 통상 문구로, Ⅳ장 HCG 소개는 표준 장 그대로 들어간다(plan-table 이 맞춰 보여 줌). 바꾸지 않는다.
- 「HCG 표준」으로 표시된 장(Why HCG 솔루션 · 실행지원, 수행 조직 · 투입 인력)은 계획 뒤에 저절로 붙는다. 사용자가 빼 달라고 하면 plan.json 에서 그 줄만 지운다.
- 계획 표 위에 한 줄로 구성을 알린다: 「Ⅰ장 a장(Why HCG b장 포함) · Ⅱ장 c장([참고] d장) · Ⅲ장 3장 · HCG 소개 5장」.

## 4. 만들기(멈추지 않음)
1. `hcgd build "<작업 폴더>"` → `prompts`(보통 5개: prompt · answer 경로).
2. **고쳐 쓰기 에이전트**를 묶음 수만큼 **한 번에 동시에** 부른다(한 메시지에 Agent 호출 여러 개). 각각 일 = 「요청문 <prompt> 를 읽고 답을 <answer> 에 써라」. 요청문 내용을 직접 읽지 않는다(길다).
3. `hcgd apply "<작업 폴더>"` → `fix` 가 있으면 **다듬기 에이전트**에게 일 = 「<fix> 를 읽고 <fix_answer> 에 써라」 → `hcgd fix "<작업 폴더>" 1` → 또 `fix` 가 있으면 다듬기 에이전트 → `hcgd fix "<작업 폴더>" 2`. 그 뒤 남은 것은 노란 딱지 · 확인 목록으로 간다(더 줄이지 않음).
4. `hcgd names "<작업 폴더>"` → `prompt` 가 있으면 다듬기 에이전트로 같은 방식.
5. `hcgd finish "<작업 폴더>"` → `file` · `checks_file` · 종류별 건수.

## 에이전트 부르기
Agent 도구로 `subagent_type: "general-purpose"` 와 아래 `model` 을 준다. prompt 는 이 형식 그대로:
「먼저 <지침 파일> 을 Read 로 읽고 그 지침을 그대로 따른다. Read · Write 도구만 쓴다. 일: <각 단계의 일 문장>」

| 에이전트 | model | 지침 파일 |
|---|---|---|
| 계획 | `opus` | `<스킬>\references\agents\planner.md` |
| 고쳐 쓰기 | `opus` | `<스킬>\references\agents\rewriter.md` |
| 다듬기 | `sonnet` | `<스킬>\references\agents\fixer.md` |

## 5. 마무리 보고
- 파일 경로 2개(pptx · 확인목록.md), 걸린 시간, 확인 목록 건수(종류별), 다른 고객 이름 남은 수(`names_left`, 0 이 정상).
- 다음 할 일: PowerPoint 로 열기 → 장 위 노란 딱지(「확인 · 값 넣기」 「확인 · 그림 속 글」 등)를 보며 손본 뒤 딱지 지우기(「HCG 장표」 작업창 Check 탭 또는 확인목록.md).
- 공시 숫자를 썼으면 「각주의 DART 출처를 한 번 확인」을 덧붙인다.

## 지킬 것
- 고객 숫자 · 사실을 지어내지 않는다. 모르는 것은 ○○, 차트는 빈 값.
- 다른 고객 그림은 지우지 않는다(노란 딱지만).
- 열쇠 글자 · 회사 메일 외 개인 정보를 대화에 옮기지 않는다.
- 원본 제안서 폴더(OneDrive 「02 Proposal」 등)에는 쓰지 않는다.
- 단계 명령이 `error` 를 내면 다시 돌리기 전에 사용자에게 알린다.

## 입력 예시
```
아래 TCK 회의록으로 제안서 Draft 만들어 줘.
자료 폴더: C:\Users\<나>\Downloads\TCK 자료      ← 없으면 이 줄은 빼도 됨(카드에서 물어봄)

[회의록] 2026.11.05 TCK 인사팀 미팅
- 참석: TCK 인사팀장 · 인사담당, HCG ○○
- 배경: 경영진 지시로 평가체계 고도화 검토 …
- 요청 범위: …
- 일정: …
```
