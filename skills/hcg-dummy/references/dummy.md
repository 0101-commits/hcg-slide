# Dummy 제안서 만들기

사용자가 「Dummy 제안서」「더미 만들어 줘」라고 하며 고객사명 · 회의 내용 · 주요 스콥을 주면, 목차와 장마다 유형 · 어깨끈 · 핵심 문장을 정해 **Dummy 장**을 만든다. 실제 장표는 「HCG 장표」 작업창의 「Library로 채우기」가 유형마다 지난 제안서 장표로 바꿔 넣는다.

## 1. 입력 확인
- 꼭 필요: 고객사명, 업종(금융 · 자동차·기계·중공업 · 식품·소비재 · 지주·그룹 · IT·플랫폼·게임 · 화학·소재·에너지 · 공공·연구 · 건설·부동산 · 바이오·제약 · 유통·서비스·레저 · 기타 중), 회의 내용(메모), 주요 스콥, 기간, 분량.
- 분량 = 본문(Ⅰ~Ⅲ장) 장수. 표지 · 목차 · 간지 · Ⅳ HCG 소개는 빼고 센다. 일반 40장(실제 제안서 본문은 37~69장) · 상세 50장 · 약식 30장. 말하지 않으면 일반 40장.
- 빠진 것만 묻는다.

## 2. 목차 · 장 계획(실제 제안서 6건 비교로 정한 흐름)
장마다 `types.md` 의 유형 코드 하나를 고른다. 같은 유형이 여러 장이어도 됨. 표지 · 목차 · 간지는 계획하지 않는다(작업창 · 사람이 넣음). 가격 장표는 만들지 않는다.

### 장 수 나누기(일반 40장 기준)
Ⅰ 제안 개요 약 11장(Why HCG 4~5장 포함) · Ⅱ 수행 방안 약 25장 · Ⅲ 수행 체계 4장 · Ⅳ HCG 소개 4~5장(분량 밖). 분량이 다르면 같은 비율로.

### Ⅰ 제안 개요(이 순서, 장마다 다른 이야기)
1. 고객 이해 · 추진 배경 1~2장(T103 · T101) — 고객 사업 현황 · 업황에서 과제 필요성으로. 어깨끈 「제안 배경    사업현황」.
2. 환경 변화 · HR Trend 1장(T102) — 과제 주제(평가 · 보상 · 직급 · 조직문화 등)의 최근 흐름. 장이 넉넉하면 「[참고] 국내 선도기업 HR Trend」 1장 더.
3. 現 제도 이슈 · 가설적 이슈 1~2장(T104 · T105 · T210) — As-is/To-be 대비. 고객 내부 방향이 정해지기 전이면 To-be 는 「(잠정 案)」.
4. 프로젝트 목적 및 범위 1장(T106) — 범위 = Ⅱ장 모듈 순서 그대로.
5. Why HCG(이 순서):
   - 「제안 특징 및 장점    Why HCG」 요약 1장(T406) — 강점 3가지
   - 「Why HCG    1. 주제에 대한 전문성 보유」 1장(T405)
   - 「[참고] 유사프로젝트 수행사례    A사」 1장(T405 · T206)
   - 「Why HCG    2. Cutting-Edge 방법론」 1장(T407). 범위에 talenx · SaaS 같은 시스템이 있으면 「Why HCG    2. 자체 성과관리 솔루션 보유」(T408)
   - 「Why HCG    3. 지속적인 변화관리 지원」 1장(T406)
- 배경 = 회사 상황, 트렌드 = 바깥 흐름, 이슈 = 제도 문제, 목적 = 해결 방향. 같은 이슈를 여러 장에서 되풀이하지 않는다. 추진 전략(T108) · 기대효과(T109)는 장이 넉넉할 때만.

### Ⅱ 수행 방안(모듈마다 번호)
1. (장이 넉넉하면) Overall Approach 1장(T201) — 단계 = 아래 모듈 순서.
2. 「1. 현황 진단 및 방향성 수립」 모듈 — **기본으로 넣는다**. Approach(T204 · T202 — Document Review · 인터뷰/서베이 · 벤치마킹) · Interview & Survey(T205) · Benchmarking(T206) · 이슈 및 개선 방향성(T207 · T208) 중 2~4장. 고객이 진단을 최소로 해 달라고 했을 때만 1장으로 줄인다.
   - 과제 이름이 진단(조직진단 · 조직문화 진단 · 인사 진단)이면 진단 모듈이 Ⅱ장의 중심: Ⅱ장의 40~50%를 진단 방향 · 진단 Framework · 진단 항목별 Survey/Interview 설계 · 조직운영 분석 · Benchmarking · 진단 결과 · 개선 방향성으로 쓴다.
3. 「2. …」 「3. …」 = 요청 범위 항목을 고객 RFP · 회의 순서대로 모듈로. 모듈마다 2~6장 — 변화 Trend → 설계 방향 · Framework → 상세 설계(유형 · 대안 · 기준, T209 · T211~T216) → Simulation(T217) · 연계 방안 순.
4. 주요 모듈 설계 장 뒤에 [참고] 장(T407 HCG 자산 · T405 · T206 수행 사례 · T220 산출물 예시). [참고]는 Ⅱ장의 15~25%.
5. 마지막 모듈 「N. 변화관리 및 실행지원」 1~2장(T219 — 단계별 Roll-out · 커뮤니케이션, 시스템 범위면 시스템 셋업).
- 제도 설계 장(T211~T216)은 스콥에 맞는 HR 모듈을 mod 에 적는다(평가 · 보상 · 직급 · 직무 · 조직 · 육성 · 조직문화 · 인력 · 시스템 · 채용 · 노사 · 공통 중).

### Ⅲ 수행 체계 · Ⅳ HCG 소개
- Ⅲ = 추진 일정(T301) · 수행 조직(T302) · 투입 인력(T303) · 프로젝트 관리방안(T304) 1장씩. 핵심 문장은 통상 문구:
  - T301 「본 프로젝트는 다음과 같은 일정&절차에 따라 총 N주간 진행될 예정임」(기간은 회의 내용대로, 모르면 「총 N주간」 빼기)
  - T302 「본 프로젝트의 성공적 수행을 위하여 최적의 경험과 역량을 갖춘 컨설턴트를 투입하여 팀을 구성할 것임」
  - T303 「본 프로젝트 참여 인력의 주요 이력사항은 아래와 같음」
  - T304 「HCG는 프로젝트 품질제고를 위한 일정/품질/위험/보안관리 및 지식전수/사후관리/실행지원 등을 통해 프로젝트의 성공 및 컨설팅 결과의 실행력 제고에 기여하고자 함」
- Ⅳ = HCG Overview(T401) · 사업 영역 · 컨설팅 서비스 영역(T402) · 주요 고객사(T403) · Long-term Relationship(T404). 2차 제안 · 기존 고객이면 뺀다.

### 어깨끈(head) — 나누는 곳은 공백 4칸, 고객사명은 넣지 않는다
- Ⅰ장 · Overall Approach · 추진 일정 = 「제안 배경    장 이름」 또는 장 이름 하나(「제안 배경    HR Trend」 「프로젝트 목적 및 범위」 「Overall Approach」 「추진 일정」)
- Why HCG 장 = 위 5번처럼 번호
- Ⅱ장 설계 장 = 「N. 모듈    장 이름」 또는 「N. 모듈    세부    장 이름」(「1. 현황 진단 및 방향성 수립    Approach」 「3. 보상제도 개선    기본급 인상    평가인상 방식」). 번호 · 모듈 이름은 목적 및 범위 · Overall Approach 와 같게.
- [참고] 장 = 「[참고] 장 이름」 하나(「[참고] HCG 역량모델 활용」)

### 핵심 문장(msg)
- 2줄, 70~110자. 이유(고객 상황 · 이슈 · 요청)에서 결론(할 일 · 효과)으로 잇는다. 끝은 「~함 · ~임 · ~시점」.
- 예: 「반도체 업황 회복으로 성장세가 이어지고 있어, 중장기 성장 목표의 실행력을 높이기 위한 성과관리 체계 고도화가 필요한 시점」 「업무특성과 수행방식에 따른 성과 창출 방식의 차이를 고려하여 사무/생산의 평가방식을 구체화 함」
- 회의 내용 · 고객 자료의 사실 · 숫자만 쓰고 지어내지 않는다(필요하면 「(가정)」).

## 3-A. Claude for PowerPoint 에서 — Dummy 장을 직접 만든다
Office 명령 실행 도구(`execute_office_js`)로 맨 뒤에 장을 하나씩 더한다. 장마다 아래 표시(태그)를 꼭 붙인다 — 작업창이 이 표시로 Library 장표를 고른다.

```js
await PowerPoint.run(async (ctx) => {
  ctx.presentation.tags.add("HCG_CLIENT", "한빛소재");
  const plan = [ /* {ch, head, msg, type, mod} … */ ];
  for (const s of plan) {
    ctx.presentation.slides.add();
    await ctx.sync();
    const all = ctx.presentation.slides; all.load("items"); await ctx.sync();
    const sl = all.items[all.items.length - 1];
    const t1 = sl.shapes.addTextBox(`${s.ch}    ${s.head}`, { left: 36, top: 18, width: 880, height: 26 });
    t1.textFrame.textRange.font.size = 14; t1.textFrame.textRange.font.color = "#C00000"; t1.textFrame.textRange.font.bold = true;
    const t2 = sl.shapes.addTextBox(s.msg, { left: 36, top: 46, width: 880, height: 52 });
    t2.textFrame.textRange.font.size = 18; t2.textFrame.textRange.font.bold = true;
    sl.shapes.addTextBox("///", { left: 36, top: 120, width: 880, height: 300 });
    sl.tags.add("HCG_PLAN_TYPE", s.type);
    sl.tags.add("HCG_PLAN_HEAD", s.head);
    sl.tags.add("HCG_PLAN_MSG", s.msg.slice(0, 250));
    if (s.mod) sl.tags.add("HCG_PLAN_MOD", s.mod);
    await ctx.sync();
  }
});
```
- 한 번에 10장씩 나눠 실행해도 된다. 끝나면 「HCG 장표 → Library → Dummy 제안서 › → 모두 Library로 채우기」를 누르라고 안내한다.
- 도구가 없거나 실패하면 3-B 로.

## 3-B. Claude 앱 · Claude Code 에서(또는 3-A 가 안 될 때) — 계획 블록을 준다
답 끝에 아래 블록을 그대로 준다. 사용자가 HCG 장표 작업창 「Dummy 제안서 › 계획 붙여넣기」에 붙여넣으면 작업창이 Dummy 장을 만든다.

```
HCG_PLAN {"client": "한빛소재", "industry": "화학·소재·에너지", "slides": [
 {"ch": "제안 개요", "head": "제안 배경", "type": "T101", "msg": "…함"},
 {"ch": "제안 개요", "head": "가설적 이슈", "type": "T105", "msg": "…함", "mod": "보상"}
]}
```
- JSON 은 한 덩어리로, 큰따옴표만. 장 수만큼 slides 에 넣는다.
