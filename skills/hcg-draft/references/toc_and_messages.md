- 4부 이름은 건마다 다르지만 기능은 같음 → 섹션을 「역할」로 관리하고 표기는 고객 RFP 용어에 맞춘다(「관리방안」「프로젝트 관리」「RFP 장 번호」).
- 소개를 앞에 둔 13건 중 이유가 확인되는 것은 4건(RFP 지침). 나머지는 이유 근거 없음 → 지침이 없으면 기본값 A.
- RFP 가 형식을 강제하면 C 로 가고 HCG 표준 4부는 그 안에 흡수한다. 신용보증기금은 본문 100쪽·요약본 30쪽 제한까지 받아 7대분류로 갔다.
- 시기 흐름(건수가 적어 경향일 뿐): 2023 초반 A → 2023.09~2024.09 B → 이후 A 또는 소개 제외 → 2025 이후 익명성·분량 제한 RFP 증가.

### 추천 절차
1. 문서 유형이 약식·논의자료·무기명·2차이면 D.
2. 요청 원문이 평가 항목 순서·문구·배점을 강제하면 C.
3. 공동 제안이면 E.
4. RFP 가 업체 현황을 먼저 요구하면 B, 아니면 A.
5. 회사 소개 5장 그대로 vs 생략·축소는 맞서는 규칙임 → 신규 고객인지 · 무기명인지 · 약식·2차인지 · 분량 제한이 있는지 묻는다(`rules.md` 「맞서는 규칙」).

## 3. 섹션마다 반복되는 메시지 문형 (장별 주장 문장을 쓸 때 쓴다)

공통 3단: 「[고객 상황] → [그래서 필요한 것] → [HCG 접근의 한 줄 차별점]」

| 섹션 | 문형 | 실제 예 |
|---|---|---|
| 제안 배경(헤드) | [외부 환경 변화] → [고객의 현 위치] → [제도·관행의 한계] → [그래서 OO 개편 필요]. 17건에서 같은 순서 | 철강 성공 유산 위의 소재 전환 → 과거 성공 방정식이 족쇄가 되는 역설(포스코홀딩스) · 급성장하는 양극재 시장·인력난이 Agile 조직·직무/시장가치 기반 인사제도를 요구(STM) |
| 제안 배경(해결 제시) | 「[접근]은 양자택일이 아니라 연결」 | 문제는 OKR이냐 MBO냐가 아니라 평가/보상 연계 방식(크래프톤) · 법 준수는 기본, 구성원 몰입 환경까지 진단하는 예방적 접근(한화손보) |
| 가설적 이슈 | 고객 자료의 수치로 문제 가설 + 「가설적」 표시, 진단 단계에서 검증. 좌 문제 3~4개 / 우 개선 방향 쌍 | 가설적 통합 방안(쿠리타한수) |
| 목적·범위 | 목적 한 문장 + 범위 도식 1장(모듈 박스 + Optional 표시) | 형평성 · 경쟁력 · 명확성 3요소(이노크라스) |
| Why HCG | 3축 나란히(아래 4절) | 26건에 별도 구간(3~8장) |
| 수행 방법 | 전체 흐름 1장(진단 → 이슈 → 개선안 → 실행계획이 한 줄) → 단계별 소목차 → 영역마다 「변화 흐름 → 방향 → 설계 → [참고]」 | 전체 흐름 장표가 11건 이상에서 첫 장 |
| 일정·조직 | N주 · 보고 M회 간트 → 조직도(Steering → PD → Advisor) → 투입 인력 이력 | 12주 · 3회 보고(목암생명과학연구소) · 검증된 팀 · 8주(주성엔지니어링) |
| 회사 소개 | 수치 중심 5장 | 13건 이상이 같은 5장 |

- 대비형 제목이 자주 나온다: 일반 방식 vs Workflow 방식 · 전통 컨설팅 vs AI 기반 표준설계도 · 누적식 vs 비누적식.
- 고객이 쓰는 단어를 피하는 경우가 있다(파라다이스: 회의에서 「직무평가 단어는 함정카드」 → 시장가치 연계 평가로 표현). 평가라는 단어 자체를 피해 「종합리뷰」(CT)로 쓴 예도 있음.
- 장표마다 결론 → 시사점 칸 · so-what 한 문장(차트 왼쪽 2/3, 시사점 오른쪽 1/3).
- 지시 충돌: RFP 가 「모호한 표현 불가」를 요구하는데 덱은 「가설적/예시적」 라벨이 많음 → 확정 어미 + 라벨로 완충.

### 모듈 순서
- 평가 → 보상 → 직급/승진: 성과 관리가 출발점일 때(5건). 직급/승진 → 평가 → 보상: RFP·고객 요청의 출발점이 직급·직무일 때(5건). 현황진단은 거의 항상 첫 모듈(12건, 진단 방법 3축: 문헌·인터뷰/서베이·벤치마킹). 변화관리·Roll-out 은 마지막.
- 평가 모듈 표준 흐름: 변화 Trend → 가설적 방향 → 평가모델 옵션(전통-MBO-OKR) → 업적(KPI Cascading · Check-in · BII · CFR) → 역량 → 다면진단 → 인정·피드백 → 인재 Snapshot/Talent Session → 운영체계(Calibration) → 결과 활용.
- 보상: 보상전략(Pay Level/Mix) → 기본급 체계(Pay Band) → 평가·승진 인상·Migration → 변동급·성과급 유형·배분 → Simulation.
- 직급/승진: 변화 Trend → 직급 단계 대안(2~4단계) → 호칭·역할 → 승진 기준·절차.
- 컨설팅 장표 쌍: 모듈마다 「방법론(Process & Output Image) + 방향성&아웃풋(가설적 To-Be)」.

## 4. Why HCG 3축

| 시기 | 3축 |
|---|---|
| 2023.04~10 | 다수 HR Practice(산업·주제 전문성) · 데이터 분석 기반 컨설팅 · 실행 지원(ASP) |
| 2024.05~09 | 컨설팅 전문성 · 자체 솔루션(talenx 등) · 변화관리/리더십 교육 |
| 2025~2026 | 전문성 · 근거 기반(방법론·Data Analytics) · 실행지원(변화관리·ASP) — 13건 |
| 변형 | 이해·경험·벤치마킹(파라다이스) · 두산 이해·주제 전문성·유관 산업 이해(두산에너빌리티) · 노무 전문가 협업(한화손보) |

- 근거는 레퍼런스 중심 3꼭지로. 결과 단정(「성공적인 ~ 실시」)이 아니라 「경험을 보유함」·사례형으로(규칙 W2).
- 노조·PMI 과제면 「소통·변화관리」 축. 고객이 HCG 시스템 프로젝트를 했거나 시스템이 주제가 아니면 시스템 축은 뺌(맞서는 규칙).
- 공통 Why HCG 문구가 과제 유형과 안 맞는 일이 있음(포스코홀딩스 「성공적인 제도 개선」) → 쓰기 전에 문구를 과제에 맞게 바꿀지 확인.

## 5. 맞춤 방식은 장표 위치로 정해진다

| 방식 | 해당 장표 |
|---|---|
| 새로 작성 | 제안 배경 · 가설적 이슈 · 목적·범위 · 고객 고유 Approach (거의 모든 건) |
| 참고 제안서 장표 + 구조 재구성 | 수행 방법 본문(Overall Process · 평가 운영체계 · 성과급 유형 · 시뮬레이션 · Gap · Phase 개요) |
| 수치 교체 | 일정(간트) · 투입 인력 이력 · 수행 실적 표 · 회사 현황 수치 |
| 이름 교체(+수치) | 표지 · 목차 · EOD · 회사 소개 5장 · 수행조직 · 관리 방안(품질·보안·위험) |
| 참고 + 익명화 | [참고] 사례 · 벤치마킹 사례 |

- 장표 종류별 기본값: Why HCG 3축은 이름만(과제에 안 맞는 문구는 수정), 시뮬레이션·Gap Closing·평가운영체계·보상 일반론은 공통/참고 + 구조 재구성.
- 첫 통합 초안은 최종과 40~70%만 겹치고 장표의 38~43%가 최종에서 빠진다. 순서 바뀜은 적고(중앙 2곳) 고침은 주로 삭제·신설 → 초안은 절반이 바뀔 것을 전제로 장표 묶음 단위로 켜고 끌 수 있게 낸다. 재사용 비율을 「수주에 좋은 값」으로 최적화하면 안 된다.
- 첫 초안 약 50~60%는 이름·수치 교체와 틀 재활용으로 도달하고 나머지 40~50%가 고객 맞춤 작업임.

## 6. 업종·과제별 참고

- 업종이 바꾸는 것: 제안 배경 차트·이슈, 사례 Back-up, 일부 모듈(생산직·영업·주재원·BU). 모듈 본문 틀(평가·보상·직급)은 업종과 무관하게 같음.
- 제조·소재: 생산직·사무직 이원 설계가 반복(사무 250명·생산 300명 구분 등). 금융·보험: 노무법인 업무 범위 도식과 Pay Band·연봉등급·시뮬레이션 비중이 큼. 공공·공기업: RFP 평가항목 순서로 목차 고정, 관리 방안이 큼, 가격은 별첨. 바이오·연구: OKR 기반 상시 점검 평가, 임원 평가·퇴직 예우는 [참고]. 스타트업·소규모: 대기업용 설계 장표(Pay Band·Payout Curve·시뮬레이션) 제외.
- 업종 설명 장표는 기본 「포함」, 사람이 뺀다. 업종 이해가 약하면 시장·트렌드 2장으로 보여 준다.
- 회사 소개 수치 갱신 누락(롯데알미늄: 5장을 가져오고 수치를 갱신하지 않음) 사례 → 수치는 한 곳(수치 표)에서 관리.
